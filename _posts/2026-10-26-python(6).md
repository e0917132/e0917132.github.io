## **1. 클래스 상속(inheritance)**

**상속**은 기존 클래스의 **속성과 메소드를 그대로 물려받아** 새로운 클래스를 만드는 것이다.

- 물려받은 것에 **기능을 추가**하거나 **변경**해서 새 클래스를 정의할 수 있다.
- 같은 코드를 반복해서 쓰지 않아도 되므로 **코드 재사용성**이 높아진다.
- 예: **자동차** → **승용차**, **트럭** (승용차와 트럭은 모두 자동차의 특징을 가진다)

### **부르는 이름**

| **물려주는 클래스** | **물려받는 클래스** |
| --- | --- |
| 부모 클래스 (Parent) | 자식 클래스 (Child) |
| 슈퍼 클래스 (Super) | 서브 클래스 (Sub) |
| 기반 클래스 (Base) | 파생 클래스 (Derived) |

세 쌍 모두 같은 뜻이다. 시험에는 어떤 이름으로든 나올 수 있으니 짝을 지어 기억해 두자.

### **기본 문법**

```
class 서브클래스(슈퍼클래스):
    # 서브클래스 내용 코딩
```

클래스 이름 뒤 **괄호 안에 부모 클래스 이름**을 쓰면 상속이 된다.

### **예제: 자동차 → 승용차, 트럭**

```python
class Car:
    # 자동차의 속성(색상, 속도 등)
    color= ""
    speed= 0

    def __init__(self, color, speed):
        self.color= color
        self.speed= speed

    # 자동차의 동작(속도 올리기, 속도 내리기)
    def upSpeed(self, value):
        self.speed+= value

    def downSpeed(self, value):
        self.speed-= value

class Sedan(Car):            # Car를 상속받은 승용차
    seatNum= 0              # 승용차에만 있는 속성: 좌석 수

    def getSeatNum(self):    # 승용차에만 있는 메소드
        return self.seatNum

class Truck(Car):            # Car를 상속받은 트럭
    capacity= 0             # 트럭에만 있는 속성: 적재량

    def getCapacity(self):   # 트럭에만 있는 메소드
        return self.capacity
```

### **사용해 보기**

```python
myCar= Car("빨강", 10)
sedan= Sedan("노랑", 40)  
# Sedan에는 __init__이 없지만 Car의 것을 물려받아 사용
truck= Truck("흰색", 100)

sedan.upSpeed(50)            # Car에서 물려받은 메소드
truck.downSpeed(30)
sedan.seatNum= 5            # Sedan에서 추가한 속성
truck.capacity= 500

print(sedan.speed, truck.speed)    # 90 70
print(sedan.getSeatNum())          # 5
print(truck.getCapacity())         # 500
```

**포인트**

- `Sedan` 클래스 안에는 `__init__`도 `upSpeed`도 없지만, **부모 `Car`에서 물려받았기 때문에** 그대로 쓸 수 있다.
- 반대로 부모는 자식의 것을 쓸 수 없다. `myCar.getSeatNum()`은 `AttributeError`가 난다.
- `Sedan`과 `Truck`은 형제 관계일 뿐 서로의 메소드를 공유하지 않는다. `sedan.getCapacity()`도 에러다.

### **➕ 상속 관계 확인하기: `isinstance()`, `issubclass()`**

```python
print(isinstance(sedan, Sedan))   # True
print(isinstance(sedan, Car))     # True   ← 자식 객체는 부모 타입이기도 하다
print(isinstance(sedan, Truck))   # False
print(issubclass(Sedan, Car))     # True   ← 클래스끼리의 관계 확인
```

> 💡 **"is-a 관계"** 가 성립할 때 상속을 쓴다. "승용차**는** 자동차**이다**(Sedan is a Car)"는 자연스럽지만, "바퀴는 자동차이다"는 어색하다. 바퀴처럼 "자동차가 **가지고 있는** 것(has-a)"은 상속이 아니라 속성으로 넣는다.

## **2. 메소드 오버라이딩(overriding)**

**오버라이딩**은 부모 클래스에서 물려받은 메소드를 **자식 클래스에서 다시 정의(재정의)** 하는 것이다.

1. 자식 클래스는 메소드를 물려받았으므로 원래는 다시 만들 필요가 없다.
2. 하지만 **자식에 맞게 내용을 바꿔야 한다면** 같은 이름으로 메소드를 다시 만들 수 있다.
3. **자식 클래스의 객체로 호출하면, 재정의된(자식의) 메소드가 호출된다.**

### **예제: 승용차는 속도 제한 150km/h**

```python
class Sedan(Car):
    seatNum= 0

    def getSeatNum(self):
        return self.seatNum

    def upSpeed(self, value):         # Car의 upSpeed를 재정의
        self.speed+= value
        if self.speed> 150:
            self.speed= 150
            print("속도는 150을 넘을 수 없습니다")
```

```python
sedan= Sedan("노랑", 100)
sedan.upSpeed(100)        # Sedan의 upSpeed가 호출됨
print(sedan.speed)
```

```python
속도는 150을 넘을 수 없습니다
150
```

```python
truck= Truck("흰색", 100)
truck.upSpeed(100)        
# Truck은 재정의하지 않았으므로 Car의 upSpeed가 호출됨
print(truck.speed)        # 200
```

### **파이썬이 메소드를 찾는 순서**

`sedan.upSpeed(100)`을 실행하면 파이썬은 **객체 자신의 클래스부터 위로 올라가며** 메소드를 찾고, **가장 먼저 찾은 것**을 실행한다.

```
sedan.upSpeed(100)
      │
      ▼
 Sedan에 upSpeed 있나? ──있음──▶ Sedan.upSpeed 실행 (오버라이딩)
      │ 없음
      ▼
 Car에 upSpeed 있나?   ──있음──▶ Car.upSpeed 실행
      │ 없음
      ▼
 AttributeError
```

그래서 자식에 같은 이름의 메소드가 있으면 부모의 메소드는 **가려질 뿐 지워지지 않는다.** `Car` 객체나 `Truck` 객체는 여전히 원래의 `Car.upSpeed`를 사용한다.

> ➕ **`__init__`도 오버라이딩된다.** 생성자 역시 메소드이므로, 자식 클래스에 `__init__`을 새로 만들면 부모의 `__init__`은 **자동으로 실행되지 않는다.** 이때 생기는 문제와 해결법이 바로 다음 절의 `super()`다.
>

## **3. ➕ `super()`: 부모의 기능을 살리면서 확장하기**

위의 `Sedan.upSpeed`를 다시 보자.

```python
def upSpeed(self, value):
    self.speed+= value  # ← Car.upSpeed와 똑같은 코드를 또 썼다
    if self.speed> 150:
        self.speed= 150
```

부모의 코드를 **복사해서 다시 쓰는 것**은 상속의 목적(재사용)에 어긋난다. 나중에 `Car.upSpeed`를 고치면 `Sedan`도 따로 고쳐야 한다. `super()`를 쓰면 **부모의 메소드를 호출한 뒤 필요한 부분만 덧붙일** 수 있다.

```python
class Sedan(Car):
    def upSpeed(self, value):
        super().upSpeed(value)       # 부모(Car)의 upSpeed 실행
        if self.speed> 150:         # 승용차만의 추가 기능
            self.speed= 150
            print("속도는 150을 넘을 수 없습니다")
```

| **방식** | **코드** | **의미** |
| --- | --- | --- |
| 완전히 새로 정의 | 부모를 호출하지 않음 | 부모의 동작을 **대체** |
| `super()` 활용 | `super().메소드()` 호출 후 추가 | 부모의 동작을 **확장** |

### **가장 많이 쓰는 곳: 자식 생성자에서 `super().__init__()`**

승용차를 만들 때 좌석 수도 한 번에 받고 싶다면 `Sedan`에 `__init__`을 새로 만들어야 한다.

```python
class Sedan(Car):
    def __init__(self, color, speed, seatNum):
        super().__init__(color, speed)   
        # color, speed 초기화는 부모에게 맡김
        self.seatNum= seatNum   # 승용차만의 속성만 직접 초기화

    def getSeatNum(self):
        return self.seatNum

sedan= Sedan("노랑", 40, 5)
print(sedan.color, sedan.speed, sedan.getSeatNum())   # 노랑 40 5
```

### **⚠️ `super().__init__()`을 빼먹으면?**

```python
class Car:
    def __init__(self, color, speed):
        self.color= color
        self.speed= speed

    def upSpeed(self, value):
        self.speed+= value

class Sedan(Car):
    def __init__(self, color, speed, seatNum):
        self.seatNum= seatNum    # super().__init__() 호출을 빼먹음

sedan= Sedan("노랑", 40, 5)
sedan.upSpeed(10)
# AttributeError: 'Sedan' object has no attribute 'speed'
```

자식의 `__init__`이 부모의 `__init__`을 **가렸기 때문에** `self.color`, `self.speed`가 한 번도 만들어지지 않았다.

> 💡 `super()` 대신 `Car.__init__(self, color, speed)`처럼 부모 이름을 직접 써도 동작한다. 다만 부모 클래스 이름이 바뀌면 같이 고쳐야 하고, `self`도 직접 넘겨야 하므로 **`super()`를 쓰는 것이 표준**이다.

## **4. 용어 차이: overwrite vs override vs overload**

이름이 비슷해서 시험에 자주 나오는 세 용어다.

| **구분** | **overwrite (덮어쓰기)** | **override (재정의)** | **overload (중복 정의)** |
| --- | --- | --- | --- |
| 의미 | 한 구현을 다른 구현으로 **완전히 교체** | 상속받은 메소드의 내용을 **자식에 맞게 수정** | **이름만 같고** 매개변수가 다른 메소드를 **새로 정의** |
| 키워드 | replace, over | change, modify, customize, take over | new |
| 기존 것 | **파괴됨**, 무효화 | 부모 메소드는 **그대로 남아 있음** | 기존 메소드도 **함께 존재** |
| 조건 | — | 상속 관계, 메소드 이름·매개변수가 같음 | 매개변수의 **개수나 타입이 달라야** 함 |
| 비유 | 파일을 같은 이름으로 저장해서 원본이 사라짐 | 부모님 레시피를 내 입맛에 맞게 바꿔 씀 (부모님 레시피는 그대로) | 이름은 같은 "더하기"지만 2개짜리, 3개짜리 버전이 따로 있음 |

```
overwrite :  [기존 구현] ──교체──▶ [새 구현]          (기존 것은 사라짐)

override  :  [부모.upSpeed()]                     (부모 것은 그대로)
                   │ 상속 후 재정의
                   ▼
             [자식.upSpeed()]

overload  :  [add(a, b)]   [add(a, b, c)]      
(같은 이름, 매개변수만 다름, 둘 다 존재)
```

> ⚠️ **강의 자료 보충**: 강의 자료의 "override는 메소드명, 매개변수, **반환타입**이 모두 같아야 함"과 overload 설명은 **Java, C++ 같은 언어 기준**이다. 파이썬은 반환 타입을 선언하지 않으므로 "반환타입"은 따지지 않으며, overload는 다음 절처럼 파이썬에서 다르게 동작한다. 시험에서 용어 정의를 물으면 강의 내용대로 답하되, 실제 파이썬 동작은 구분해서 알아 두자.

## **5. ➕ 파이썬에는 오버로딩이 없다?**

Java에서는 매개변수 개수가 다른 같은 이름의 메소드를 여러 개 만들 수 있다. 파이썬에서 똑같이 해 보면:

```python
class Calc:
    def add(self, a, b):
        return a+ b

    def add(self, a, b, c):      # 같은 이름으로 다시 정의
        return a+ b+ c

c= Calc()
print(c.add(1, 2, 3))   # 6
print(c.add(1, 2))      # TypeError: Calc.add() missing 1 required positional argument: 'c'
```

두 번째 `add`가 첫 번째 `add`를 **덮어써 버렸다.** 파이썬에서 메소드 이름은 변수 이름과 같아서, 같은 이름으로 다시 정의하면 마지막 것만 남는다. 즉 파이썬에서 이렇게 쓰면 overload가 아니라 **overwrite**가 일어난다.

### **파이썬식 해결법: 디폴트 파라미터와 가변 인자**

```python
class Calc:
    # 방법 1: 디폴트 파라미터
    def add(self, a, b, c=0):
        return a+ b+ c

    # 방법 2: 가변 인자 (개수 제한 없음)
    def add_all(self, *nums):
        return sum(nums)

c= Calc()
print(c.add(1, 2))             # 3
print(c.add(1, 2, 3))          # 6
print(c.add_all(1, 2, 3, 4))   # 10
```

강의 자료의 "기능이 같은데 매개변수만 다를 경우 메소드 이름을 각자 정의할 필요 없음"이라는 오버로딩의 **목적**을, 파이썬은 메소드 하나로 달성한다.

### **연산자 오버로딩: 파이썬에서 말하는 "오버로딩"**

파이썬에서 overloading이라고 하면 보통 **연산자 오버로딩**을 뜻한다. `+`, `==`, `print()` 같은 기본 동작을 내 클래스에 맞게 정의하는 것으로, 실제로는 모든 클래스의 조상인 `object`의 **특수 메소드(매직 메소드)를 오버라이딩**하는 것이다.

```python
class Car:
    def __init__(self, color, speed):
        self.color= color
        self.speed= speed

    def __str__(self):                 # print()로 출력할 때의 모양
        return f"{self.color} 자동차 ({self.speed}km/h)"

    def __add__(self, other):          # + 연산자의 동작
        return self.speed+ other.speed

a= Car("빨강", 10)
b= Car("파랑", 20)

print(a)        # 빨강 자동차 (10km/h)
print(a+ b)    # 30
```

`__str__`을 정의하지 않으면 `print(a)`는 `<__main__.Car object at 0x109c6e660>` 같은 알아보기 힘든 값을 출력한다.

| **특수 메소드** | **호출되는 상황** |
| --- | --- |
| `__init__` | 객체 생성 `Car()` |
| `__str__` | `print(객체)`, `str(객체)` |
| `__add__` | `객체 + 객체` |
| `__eq__` | `객체 == 객체` |
| `__lt__` | `객체 < 객체` (정렬할 때도 사용) |
| `__len__` | `len(객체)` |

> 💡 18강에서 "list, str도 클래스"라고 했던 것을 떠올리자. `[1, 2] + [3]`이 리스트를 이어 붙이고 `"a" + "b"`가 문자열을 이어 붙이는 것도 각 클래스가 `__add__`를 다르게 정의해 두었기 때문이다.
>

## **6. ➕ 다형성(polymorphism)**

**다형성**은 **같은 이름의 메소드를 호출해도 객체의 종류에 따라 다르게 동작하는 것**이다. 오버라이딩이 있기 때문에 가능하다.

강의 연습문제의 `Person`, `Student`, `Employee`가 좋은 예다.

```python
class Person:
    def __init__(self, name, age):
        self.name= name
        self.age= age

    def work(self, minute):
        print(f"{self.name}은{minute}분동안 일합니다.")

class Student(Person):
    def work(self, minute):                       # 오버라이딩
        print(f"{self.name}은{minute}분동안 공부합니다.")

class Employee(Person):
    def work(self, minute):                       # 오버라이딩
        print(f"{self.name}은{minute}분동안 업무를 합니다.")

people= [Person("Aaron", 50), Student("Lisa", 28), Employee("Bob", 25)]

for pin people:
    p.work(60)       # 똑같은 코드인데 객체마다 다르게 동작
```

```
Aaron은 60분동안 일합니다.
Lisa은 60분동안 공부합니다.
Bob은 60분동안 업무를 합니다.
```

반복문 안의 코드는 객체가 어떤 종류인지 **신경 쓰지 않고** `work()`만 호출한다. 나중에 `Teacher` 클래스를 추가해도 반복문 코드는 고칠 필요가 없다. 이것이 객체지향의 큰 장점이다.

> 💡 `Student`와 `Employee`에는 `__init__`을 적지 않았다. 부모 `Person`의 `__init__`과 내용이 완전히 같기 때문이다. 새 속성을 추가할 때만 `__init__`을 만들고 `super().__init__()`을 호출하자.

## **7. ➕ 더 알아보기: `object` 클래스, 다중 상속과 MRO**

### **모든 클래스의 조상, `object`**

부모를 적지 않은 `class Car:`는 사실 `class Car(object):`와 같다. 파이썬의 모든 클래스는 자동으로 `object`를 상속받는다. 그래서 아무것도 정의하지 않은 클래스도 `__str__`, `__eq__` 같은 기본 메소드를 가지고 있다.

```python
print(Sedan.__mro__)
# (<class '__main__.Sedan'>, <class '__main__.Car'>, <class 'object'>)
```

`__mro__`(Method Resolution Order, 메소드 탐색 순서)는 2절의 "메소드를 찾는 순서"를 그대로 보여 준다. **Sedan → Car → object** 순서로 찾는다.

### **다중 상속**

파이썬은 부모를 **여러 개** 둘 수 있다. (Java는 불가능)

```python
class Electric:
    def charge(self):
        print("충전 중")

class ElectricSedan(Sedan, Electric):   
# 부모 두 개 (Sedan은 1절의 버전)
    pass

es= ElectricSedan("흰색", 0)
es.upSpeed(30)    # Sedan → Car에서 찾음
es.charge()       # Electric에서 찾음
```

부모들에 같은 이름의 메소드가 있으면 **괄호 안에 먼저 적은 부모가 우선**이다. 다중 상속은 구조가 복잡해지기 쉬워서, 입문 단계에서는 "가능하다"는 것과 "왼쪽 부모가 우선"이라는 것 정도만 알아 두면 충분하다.

## **8. ➕ 자주 발생하는 실수와 에러**

| **상황** | **원인** | **해결** |
| --- | --- | --- |
| `AttributeError: 'Sedan' object has no attribute 'speed'` | 자식에 `__init__`을 만들고 `super().__init__()` 호출을 빼먹음 | 자식 `__init__` 첫 줄에 `super().__init__(...)` |
| 에러는 없는데 속성 값이 0이나 빈 문자열 | 위와 같은 원인인데, 부모의 **클래스 변수**가 에러를 가림 (3절 참고) | 속성은 `__init__`에서 `self.`로 만들기 |
| `TypeError: __init__() missing 1 required positional argument: 'seatNum'` | 자식 생성자에 매개변수를 추가했는데 객체 생성 시 값을 안 줌 | `Sedan("노랑", 40, 5)`처럼 전달 |
| `TypeError: ... missing 1 required positional argument` (메소드) | 같은 이름 메소드를 두 번 정의해서 앞의 것이 덮어써짐 (5절) | 디폴트 파라미터, `*args` 사용 |
| `AttributeError: 'Car' object has no attribute 'getSeatNum'` | 부모 객체로 자식에만 있는 메소드 호출 | 상속은 부모 → 자식 한 방향 |
| 오버라이딩했는데 부모 메소드가 실행됨 | 메소드 이름 오타 (`upspeed`, `upSpeeed`) → 새 메소드가 따로 생김 | 이름을 대소문자까지 정확히 |
| `SyntaxError: invalid character '“'` | PPT의 둥근 따옴표(`“ ”`, `‘ ’`)를 그대로 복사함 | 키보드의 곧은 따옴표 `" "`, `' '`로 바꾸기 |

## **9. 한눈에 요약**

### **핵심 문법**

```
class Child(Parent):                       # 상속
    def __init__(self, a, b, c):
        super().__init__(a, b)             # 부모 생성자 호출
        self.c= c# 새 속성 추가

    def method(self):                      # 오버라이딩
        super().method()                   # (선택) 부모 동작 유지
        ...# 자식만의 동작 추가
```

### **핵심 용어**

| **용어** | **한 줄 설명** |
| --- | --- |
| 상속 | 부모의 속성·메소드를 물려받아 새 클래스를 만드는 것 |
| 부모 = 슈퍼 = 기반 클래스 | 물려주는 클래스 |
| 자식 = 서브 = 파생 클래스 | 물려받는 클래스 |
| 오버라이딩 (override) | 물려받은 메소드를 자식에서 **재정의** (부모 것은 그대로) |
| 오버라이트 (overwrite) | 기존 구현을 **완전히 교체** (기존 것은 사라짐) |
| 오버로딩 (overload) | 같은 이름, **다른 매개변수**의 메소드 여러 개 (파이썬은 디폴트 파라미터로 대체) |
| `super()` | 부모 클래스의 메소드를 호출 |
| 다형성 | 같은 메소드 호출이 객체 종류에 따라 다르게 동작 |
| MRO | 메소드를 찾는 순서 (자식 → 부모 → object) |
